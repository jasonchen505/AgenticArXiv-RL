# 面试讲述与追问准备

## 60 秒开场

我在开源 AgenticArXiv-RL 上做了一个论文工具 Agent 的后训练复现和推理效率项目。主问题是少调用模型时，能否保住用户任务完成率。

训练部分用 Qwen2.5-1.5B，实际跑了 QLoRA/SFT、DPO 和 GRPO。我加入同 chosen 的继续 SFT、两种子和 lr=0 对照，检查权重更新、参考冻结与旧能力保持。DPO、GRPO 都没有得到稳定收益，所以没有替换原 SFT。

后面把评测推进到完整自然请求和真实正文引用，用 Qwen3.5 的原生能力比较编排。在 8 条冻结双论文请求上，同开启思考模式的两条路径都完成 5/8，模型调用从 16 次降到 11 次，全部 token 降了 12.26%。这是小样本和原句选证任务的结果。我的贡献是把后训练与系统改进做成可追踪的实验，能说明哪些结果成立、哪些候选应该停。

## 3 至 5 分钟展开

我先把问题限定为论文工具 Agent 的任务质量与调用成本。上游提供了 ReAct 环境和训练路线，但原作者的快照、全部权重和完整视觉后端拿不到。我重建了离线真实论文环境，保留版本出处，并明确图表与正文采用抽取后端。复现到什么程度、缺少什么资产，都写进了报告。

训练用 Qwen2.5-1.5B。SFT 是 NF4/bf16 QLoRA、LoRA r16，4,776 条语言样本对应 137 个语义实例，实际 597 个优化器步。我用父任务隔离和来源记录检查训练与留出任务的关系。语言变体不等于独立任务，早期 IID/OOD 里发现的模板和程序重合也保留了审计结论。权重 SHA、训练曝光和损失掩码是我确认实验确实执行过的依据。

我重点比较了 DPO 和继续 SFT。两组从同一个 SFT 适配器出发，用同 chosen 数据、同 seed、同训练步数；DPO 的参考适配器冻结并做逐张量比较。首个匹配实验的数据池有 448 条，51 步、有效批量 4，计划曝光 204 条，不能叫完整一轮。两种子 DPO 在新参数请求上都是 45/66，同 chosen 控制为 51/66 和 52/66。首轮偏好负例是 TRAIN 合成的，后续还做过真实错误锚定配方；这些结果不能混成一轮的增益。GRPO 用同种子 lr=0 控制：学习组确实更新了 392 张量，控制不变，参考冻结，但新程序收益与旧能力保持没有同时达标。这些结果让我停止推广候选，而不是挑一个好种子。

系统部分我发现，工具都执行成功仍可能漏用户问项。评测因此检查完整请求、多论文证据、版本出处、失败恢复，以及失败和思考 token 的成本。论文身份能由公开别名确定时，省去模型规划；复杂指称回退模型。执行器按实际反馈取证，最后让模型对完整原问题选句。最新主对照是同 Qwen3.5、同开启思考模式，8 条新正文请求，复用六篇已知论文。两条路径都是 5/8，实际调用 16→11，全部 token 94,116→82,580。两条路径独立生成，逐题最终证据池、prompt、seed 和生成 IDs 相同，因此这批样本比较清楚地隔离了编排成本。关闭思考只是另外的配置成本参照。

我不会把这批结果说成生产可靠性已经保持。两个答案在 8K 思考预算内没有闭合，一个漏了学习难度排序；还有一题存在取证缺口，参考证据超过 8 句容量，仍保留在分母，绝对门槛失败。评分是助手语义审阅，输出采用原句，故障来自离线注入。工程上我做了版本锁定、只用授权 GPU、显存准入、有限超时、拒绝覆盖轨迹、全部调用计费和源文件保护。公开仓库提供原始训练记录、独立接口和 CPU 证据浏览器。若继续研究，我会先在新任务批次解决取证和输出容量，再判断有没有证据充分却选错的 TRAIN 决策值得训练。

## 常见追问

### 哪些是上游，哪些是这项工作的贡献？

上游提供工具 Agent、模型加载和 SFT/DPO/GRPO 框架。本工作完成数据与资产复现、隔离审计、训练及匹配控制、奖励/评测修复、完整请求与证据评测，以及公共身份规则和模型回退编排。不要声称自己发明了 ReAct、DPO 或 GRPO。代码与证据入口见 [CLAIMS.md](CLAIMS.md)。

### 后训练没有正增益，项目还能讲什么？

讲真实优化、控制与决策。DPO 比同 chosen 继续 SFT 差，说明不能把继续学习的效果算成偏好优化收益；GRPO 权重更新说明发生了学习，但收益与保持未达门槛。负结果有完整分母与配方，不把一次训练成功当成任务成功。当前正面结果来自受限编排对照，不来自新增 RL 收益。

### 为什么学习率为零的组还执行 optimizer？

它沿用原生训练循环、rollout 和预算，帮助排除相同流程或采样带来的变化。64 次 optimizer 调用、学习率 0，对应 0 次正学习率更新，策略权重不变。调用了 optimizer 并不意味着模型学到了东西。

### 两组最终生成 IDs 相同，是复用了缓存答案吗？

历史记录中每次 generate 都独立执行，累计 38 次调用。主对照最终输入、seed 和配置相同，因此出现相同输出；重复结果仍按独立调用计费。完整 token/事件审计在原始资产中。公开浏览器只检查公开记录之间的一致性，不独立证明生成发生过。

### 8 题 5/8 相同，能说非劣吗？

只能说这一批作者冻结请求逐题成败相同，0 胜 0 负。没有随机真实用户采样，也没有独立专家评分，更没有统计非劣检验。绝对质量门槛没有通过。

### 一次调用候选为什么还有 11 次调用？

5 条公共身份可确定的请求各 1 次最终选证；3 条复杂请求各 2 次，先模型规划再选证，合计 11。对照每题 2 次，合计 16。故障恢复由确定执行器按实际反馈处理，没有隐藏额外模型调用。

### 关闭思考便宜很多，为什么主要比较开启思考？

关闭思考的全批成本为 30,669 token，完成 4/8；开启思考压缩为 82,580 token、5/8。两种配置的预算和采样都变了。主问题要隔离编排，因此用同模型、同思考模式的主对照；这不意味着应当把开启思考路径用于所有任务。

### 是否做了真实 VLM 或线上故障恢复？

没有完成原作者的完整视觉后端复现。图表/正文是抽取式替代，主源失败是在离线环境注入，缓存恢复要求同论文、同版本，并按真实执行事件记录。不要把它说成线上故障可靠性。

### 你做了哪些 infra 工作？

两套运行环境与模型 revision 隔离，GPU4/7 准入和显存额度，超时与作业收尾，训练/推理前的源和资产 SHA 检查，输出拒绝覆盖，输入、思考、最终输出及失败 token 计量。没有 DDP、分布式训练或生产吞吐提升的实测声明。

### 公开 CPU 浏览器能验证什么？

验证原始小记录与汇总的对应关系、成本算术、未删失败题、选句 SHA 和版本 URL。它不运行模型、工具或重新判语义质量，也不重新读取权重或论文全文。真正历史重放需要服务器保留的资产和锁定环境。
